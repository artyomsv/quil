## Global Constraints

Every task's requirements implicitly include this section.

- **Build and test only through Docker.** Go and make are not installed on the host. `./scripts/dev.sh test`, `./scripts/dev.sh vet`, `./scripts/dev.sh test-race`. Never invoke `go` directly on the host.
- **Production isolation.** Never read, write, or delete anything under `~/.quil/`. Never start, stop, or signal the production daemon. Never run `./scripts/kill-daemon.*` or `./scripts/reset-daemon.*`. Never run a bare `./quil`.
- **Commit messages:** imperative mood, conventional-commit prefix, first line ≤ 72 chars. **No AI/model/vendor attribution of any kind** — no `Co-Authored-By`, no "generated with", no model or company names. Body explains what changed and why.
- **Stage by path.** `git add <explicit paths>`. Never `git add -A` — the working tree carries unrelated untracked plan documents that must stay unstaged.
- **gofmt is mandatory.** Tabs in Go files. Errors wrapped with `fmt.Errorf("...: %w", err)`; never compared with `==`.
- **Daemon handlers that touch a filesystem** run on a worker goroutine, behind their **own** single-flight `atomic.Bool` (never a shared one), under a **wall-clock** bound — not a `context.Context` alone. A context cannot interrupt a syscall already parked in the kernel; see `internal/daemon/browse.go` and `discoverWithin` in `discover.go`. Reuse `claimBlockingFSCall`/`releaseBlockingFSCall` so abandoned readers stay under the process-wide cap.
- **Response contract:** a response echoes the request's key fields **verbatim** on every path including errors and single-flight rejections. The echo is the client's staleness key, not a claim about what was read.
- **Correlation:** every request carries a per-request generation in `ipc.Message.ID` (`m.nextReqGen()`); `respondTo` echoes it. Two responses for the same content key are otherwise wire-indistinguishable.
- **TUI `Update` arms:** every branch handling an **IPC response** MUST return `tea.Batch(cmd, m.listenForMessages())`. Every branch handling a **local timer tick** MUST NOT re-arm it. Omitting the re-arm kills IPC for the session — a bug this package has shipped.
- **`listenForMessages` decode-error branches return `listenContinueMsg{}`, never `nil`.** All eleven existing arms do (`model.go:3950`…`:4042`). `return nil` means the `tea.Cmd` yields no message at all, so `Update` never reaches a re-arm branch and the listen loop dies for the rest of the session on a single malformed frame — the same failure the rule above prevents, reached by a different route. An early draft of this plan had `return nil` in every snippet; Task 1's implementer caught it.
- **A field on the wire needs a consumer, or it must not be on the wire.** If a payload carries `Truncated` — or any advisory flag — the TUI must read it AND render it. Every sibling RPC here does: `cwdBrowseTruncated` (`dialog.go:3665`), `sessionTruncated` (`dialog.go:3254`), `palette.truncated` (`palette_search.go:119`). A silently-short list reads as the whole list. Task 1 shipped this gap and had to fix it.
- **Trust boundary:** any string that now originates on a remote host must pass `sanitizeRemoteText` (`internal/tui/remotetext.go`) **at render**, never in state — raw values still flow into spawn arguments.
- **No synthetic data.** Test fixtures use obviously-synthetic values; never fabricate anything that could read as real.
- Test naming `TestFunction_Scenario_Expected`; `t.TempDir()`, `t.Setenv()`, `t.Helper()`; stdlib assertions only.

## Test harness — read this before writing any TUI test

Two facts about this package's tests that a plausible-looking sketch gets wrong:

1. **`tea.Batch` does not execute its children.** Calling `cmd()` on a batch yields a `tea.BatchMsg` and sends nothing. Every request function in this plan returns a batch, so its test MUST drive it through `runCmd` (`internal/tui/overlay_test.go:55`), which unwraps `BatchMsg` recursively — the same helper every shipped browse/discover test uses. A test that calls `cmd()` directly fails with "no message sent" against a *correct* implementation.
2. **`runCmd` walks the batched `tea.Tick` synchronously**, so it blocks for the timer's full duration. `internal/tui/main_test.go`'s `TestMain` shortens `browseTimeout` and `gitScanTimeout` for exactly this reason. **Add `kubeScanTimeout` and `recentScanTimeout` there** (Tasks 1 and 4 respectively), or every test that issues one of the new requests sleeps 8 seconds, multiplied again under `-race`. It must be done in `TestMain` and not per-test: these tests use `t.Parallel()`, so assigning the package vars mid-run is a data race.

```go
const (
	MsgKubeCtxReq  = "kube_ctx_req"
	MsgKubeCtxResp = "kube_ctx_resp"
)

// KubeCtxReqPayload is deliberately empty: kube-context discovery is
// CWD-independent, so there is no content key that could go stale. The
// per-request generation in Message.ID is the whole correlator.
type KubeCtxReqPayload struct{}

type KubeContextInfo struct {
	Name      string `json:"name"`
	Namespace string `json:"namespace,omitempty"`
	Current   bool   `json:"current,omitempty"`
}

type KubeCtxRespPayload struct {
	Contexts  []KubeContextInfo `json:"contexts,omitempty"`
	Truncated bool              `json:"truncated,omitempty"`
	Error     string            `json:"error,omitempty"`
}
```

### Decisions made here, and why

**Per-entry `Current bool`, not a top-level `Current string`.** `kubediscover.Context` already carries the flag per entry and `renderCreatePaneSetupDialog` reads `c.Current` to draw `●`. A top-level name would force the renderer to re-match by string, which is a second place to get wrong.

**The only errors reported are a timeout and a single-flight rejection.** `kubediscover.Contexts` degrades *every* failure — missing file, unreadable file, malformed YAML — to an empty list and reports nothing. An earlier draft of this work wanted "missing kubeconfig = empty, unreadable = error", but that distinction does not exist in the package, and manufacturing it means changing `kubediscover`'s documented degrade-to-empty contract as a side effect of a transport change. It also changes nothing the user can act on: there are no contexts to offer either way. Left as-is, recorded deliberately.

**No local fallback on failure** — unlike Task 2. Falling back to the laptop's kubeconfig would re-create exactly the bug this task removes. Locally the daemon *is* this machine, so nothing is lost.

**The Model keeps `[]kubediscover.Context`.** The wire type converts at the boundary in `applyKubeContexts`. Changing the field's type would churn ~10 existing test call sites in `setup_dialog_test.go` for no behavioural gain; `kubediscover.Context` is a plain data struct.

**Three-state scan phase.** The existing empty state renders `(no kube contexts found — …)`. While a request is in flight that string is a wrong answer stated confidently — the same failure this phase exists to remove. The field must distinguish scanning / ready / failed.

```go
// kubeDiscoverTimeout bounds one kubeconfig read.
//
// Contexts() reads files whose paths come from KUBECONFIG, which can name a
// network mount. kubediscover already takes a context (RD-004) and checks it
// between files, but a context cannot interrupt an os.ReadFile already parked
// in the kernel — the same distinction discoverWithin documents.
var kubeDiscoverTimeout = 10 * time.Second

// maxKubeContexts bounds what the daemon will report. The TUI caps again on
// receipt: a cap enforced only by the sender is not a cap.
const maxKubeContexts = 50

// kubeContexts is the seam the read goes through, paired with discoverCandidates
// and existing for the same reason — the branch worth pinning is the one where
// the read never returns.
var kubeContexts = kubediscover.Contexts

func (d *Daemon) handleKubeCtxReq(conn *ipc.Conn, msg *ipc.Message) {
	if !d.kubeDiscovering.CompareAndSwap(false, true) {
		respondTo(conn, msg.ID, ipc.MsgKubeCtxResp, ipc.KubeCtxRespPayload{
			Error: "another kube context scan is already running",
		})
		return
	}
	go func() {
		defer d.kubeDiscovering.Store(false)
		respondTo(conn, msg.ID, ipc.MsgKubeCtxResp, kubeCtxResponse())
	}()
}

// kubeCtxResponse is the pure half.
//
// An empty result with no Error is a real finding — "no kubeconfig here" — and
// the caller must be able to tell it from a failure, because only one of the
// two justifies telling the user there are no contexts.
func kubeCtxResponse() ipc.KubeCtxRespPayload {
	var out ipc.KubeCtxRespPayload

	ctxs, answered := kubeContextsWithin(kubeDiscoverTimeout)
	if !answered {
		out.Error = "kube context scan timed out"
		return out
	}
	if len(ctxs) > maxKubeContexts {
		ctxs = ctxs[:maxKubeContexts]
		out.Truncated = true
	}
	out.Contexts = make([]ipc.KubeContextInfo, 0, len(ctxs))
	for _, c := range ctxs {
		out.Contexts = append(out.Contexts, ipc.KubeContextInfo{
			Name: c.Name, Namespace: c.Namespace, Current: c.Current,
		})
	}
	return out
}

// kubeContextsWithin runs the read under a wall-clock budget. Same abandoned-
// goroutine trade as discoverWithin, and it shares that function's process-wide
// cap for the same reason: a parked syscall pins an OS thread.
func kubeContextsWithin(d time.Duration) ([]kubediscover.Context, bool) {
	if d <= 0 || !claimBlockingFSCall() {
		return nil, false
	}
	ch := make(chan []kubediscover.Context, 1)
	go func() {
		defer releaseBlockingFSCall()
		ctx, cancel := context.WithTimeout(context.Background(), d)
		defer cancel()
		ch <- kubeContexts(ctx)
	}()

	timer := time.NewTimer(d)
	defer timer.Stop()
	select {
	case r := <-ch:
		return r, true
	case <-timer.C:
		return nil, false
	}
}
```

```go
import (
	"log"
	"time"

	tea "charm.land/bubbletea/v2"

// kubeCtxMsg carries one kube-context response. Gen echoes the requesting
// message's ID — see kubeScanState.gen.
type kubeCtxMsg struct {
	Resp ipc.KubeCtxRespPayload
	Gen  string
}

// kubeScanTimeoutMsg fires when a kube-context request went unanswered.
type kubeScanTimeoutMsg struct{ gen string }

// kubeScanTimeout bounds one round trip from the client side. Sized like
// gitScanTimeout and for the same reason: this request can cross ssh, where a
// first round trip after an idle period pays a TCP handshake and, on Windows, a
// full authentication. Still inside the daemon's own 10 s bound, so a
// slow-but-working scan reports its result rather than being pre-empted here.
//
// A var purely so the test binary can shorten it — same TestMain override as
// browseTimeout and gitScanTimeout.
var kubeScanTimeout = 8 * time.Second

// kubeScanPhase distinguishes the three things an empty context list can mean.
// Without it the field renders "(no kube contexts found)" while a scan is still
// in flight and again when one failed — a wrong answer stated confidently in
// both cases, which is the failure this phase exists to remove.
type kubeScanPhase int

const (
	kubeScanIdle kubeScanPhase = iota
	kubeScanning
	kubeScanReady
	kubeScanFailed
)

// kubeScanState tracks an in-flight kube-context request.
//
// The zero value means "nothing in flight". Unlike browseState this needs no
// separate pending flag: the request carries no content key at all, so gen is
// the whole identity and nextReqGen never returns "".
type kubeScanState struct {
	gen   string
	phase kubeScanPhase
}

// requestKubeContexts asks the daemon which kube contexts its kubeconfig names.
//
// The daemon is the only side that can answer honestly: kubediscover run here
// parses THIS machine's kubeconfig, so against a remote host it offered the
// laptop's clusters and then launched k9s with a --context the server may not
// have — with nothing in the list hinting the wrong kubeconfig had been read.
//
// Used in local mode too, deliberately. The answer is identical when the daemon
// is local, and a path exercised only by remote sessions is one that rots.
func (m *Model) requestKubeContexts() tea.Cmd {
	gen := m.nextReqGen()
	m.kubeScan = kubeScanState{gen: gen, phase: kubeScanning}
	m.kubeContexts = nil
	m.kubeCursor = 0
	return tea.Batch(
		func() tea.Msg {
			msg, err := ipc.NewMessage(ipc.MsgKubeCtxReq, ipc.KubeCtxReqPayload{})
			if err != nil {
				log.Printf("kube discovery: encode: %v", err)
				return nil
			}
			msg.ID = gen
			m.client.Send(msg)
			return nil
		},
		kubeScanTimeoutCmd(gen),
	)
}

func kubeScanTimeoutCmd(gen string) tea.Cmd {
	return tea.Tick(kubeScanTimeout, func(time.Time) tea.Msg {
		return kubeScanTimeoutMsg{gen: gen}
	})
}

// applyKubeContexts installs a discovery answer, dropping one whose generation
// no longer matches: the dialog can be reopened on another plugin before the
// first answer lands, and applying a superseded one would offer clusters chosen
// for a pane that no longer exists.
//
// There is deliberately NO fallback to the local kubeconfig on failure — that
// is precisely the bug this replaces. Locally the daemon is this machine, so
// nothing is lost.
func (m *Model) applyKubeContexts(resp ipc.KubeCtxRespPayload, gen string) tea.Cmd {
	if gen == "" || gen != m.kubeScan.gen {
		return nil
	}
	// Same dialog-closed guard as applyGitReposPickList. A late apply is inert
	// today — nothing renders kubeContexts outside this dialog and
	// enterSetupOrSplit nils it on the next open — but "inert today" is what
	// rots, and the surrounding code has this guard everywhere else.
	if m.dialog != dialogCreatePaneSetup {
		return nil
	}
	if resp.Error != "" {
		log.Printf("kube discovery: %s", resp.Error)
		m.kubeScan.phase = kubeScanFailed
		return nil
	}

	// Cap again on receipt. The daemon caps too, but a cap enforced only by the
	// sender is not a cap once the sender is a host the user may not control.
	ctxs := resp.Contexts
	if len(ctxs) > maxKubeContexts {
		ctxs = ctxs[:maxKubeContexts]
	}
	m.kubeContexts = make([]kubediscover.Context, 0, len(ctxs))
	for _, c := range ctxs {
		m.kubeContexts = append(m.kubeContexts, kubediscover.Context{
			Name: c.Name, Namespace: c.Namespace, Current: c.Current,
		})
	}
	m.kubeCursor = 0 // Default context row
	m.kubeScan.phase = kubeScanReady
	return nil
}

// applyKubeScanTimeout turns a never-answered request into something
// diagnosable rather than a list that stays empty forever.
//
// Local timer: it must NOT re-arm listenForMessages, unlike the response
// branch. Matched on gen so a late tick from a superseded request cannot clear
// a live one.
func (m *Model) applyKubeScanTimeout(gen string) tea.Cmd {
	if gen == "" || gen != m.kubeScan.gen || m.kubeScan.phase != kubeScanning {
		return nil
	}
	m.kubeScan.phase = kubeScanFailed
	return nil
}
```

### Decisions made here, and why

**No `Homepage` on the wire.** An earlier draft carried it so a greyed row still links somewhere. It already does: the row is rendered from the *local* plugin definition, whose `Homepage` points at the tool's website — the same URL either machine would give. The field would only matter for a plugin the TUI does not define, which it cannot render at all. Dropped rather than carried unused.

**No single-flight and no worker goroutine.** The handler reads an in-memory map under an existing RLock. There is no filesystem call — `DetectAvailability` already ran at daemon start (`daemon.go:200`) and on reload (`daemon.go:1529`). Adding the goroutine machinery here would copy the *form* of the filesystem handlers without their reason.

**No per-request generation.** Every response describes the same daemon and the apply is idempotent, so last-write-wins is not merely tolerable — it is correct. This is the one RPC in the phase that genuinely does not need a correlator, and saying so explicitly is what stops the next reader from assuming it was forgotten.

**A local plugin absent from the response is marked unavailable.** If the server has no TOML for it, `spawnPane` falls back to `terminal` — the pane would open as a shell wearing the wrong name. Greying it is the honest answer. This differs from the timeout case below, and the difference is the point: an *absent* plugin is a definite finding; an *unanswered* request is not.

**On timeout or transport error, keep the local values.** A wrong grey-out silently hides a working tool; a wrong offer fails loudly at spawn. Fail toward the loud error.

**The request is issued in REMOTE MODE ONLY.** This is the one place in the phase that deliberately breaks its own "exercise the path locally too" rule, and the reason is a regression the rule would otherwise cause.

The daemon's answer is **stale by design**. `DetectAvailability` runs at daemon start (`daemon.go:200`) and on plugin reload (`daemon.go:1529`) — nowhere else — and a Quil daemon is a weeks-lived process on purpose. The TUI's own detection, by contrast, runs at every launch (`cmd/quil/main.go:456`). So in local mode, adopting the daemon's answer would replace a *fresh* answer about the right machine with a *stale* one about the same machine: install a tool today, open a fresh TUI, and it would be greyed out until the daemon restarts. That regresses every local user to fix nobody.

In remote mode the trade inverts. A stale answer about the *right* machine beats a fresh answer about the *wrong* one, which is what ships today.

**Re-detecting on request was considered and rejected as out of scope**, not as unnecessary. It is the fix that would also cover "tool installed on the server mid-session", and it is unsafe to add here: `DetectAvailability` holds `r.mu.Lock()` for the entire walk (`registry.go:186-188`) **and writes `p.Command.Cmd`** (lines 202, 272) — while `Registry.Get` hands out a raw `*PanePlugin` whose fields every caller then reads *outside* any lock. Detection racing a spawn is therefore already latent today; moving it onto every `Ctrl+N` would make it reachable. Fixing that means removing the pointer escape, which is its own change with its own blast radius. Recorded as a registry item, with the residual documented in Task 5.

```go
// SetAvailability replaces locally-detected availability with an authoritative
// answer from elsewhere — in practice the daemon, which may be on another host.
//
// A plugin absent from avail becomes unavailable rather than keeping its local
// value: if the answering side has no definition for it, spawning that type

func (r *Registry) SetAvailability(avail map[string]bool) {
	r.mu.Lock()
	defer r.mu.Unlock()
	for name, p := range r.plugins {
		p.Available = avail[name]
	}
```

```go
//
// No generation field, deliberately, and this is the one RPC in the phase where
// that is right rather than forgotten: every response describes the same daemon
// and the apply is idempotent, so a late answer says exactly what a fresh one
// would.

// requestPluginList asks the daemon which plugins its own registry can run.
//
// Availability was detected on the machine drawing the UI, which is the wrong
// machine whenever the daemon is remote: a tool installed only on the server was
// greyed out, and one installed only locally was offered and then spawned as a
// fallback terminal.
//

// does not also exercise itself locally. The daemon's answer is stale by design
// — it detects at start and on plugin reload, and runs for weeks — while the
// TUI re-detects at every launch. Locally that makes the daemon's answer
// strictly worse than the one we already have about the very same machine; a
// tool installed today would stay greyed out until the daemon restarted.
// Remotely the trade inverts: stale about the right machine beats fresh about
// the wrong one.
//
// No timeout tick: there is nothing to time out INTO. An unanswered request
// simply leaves local detection in place, which is the intended failure mode —
// a wrong offer fails loudly at spawn, a wrong grey-out hides a working tool
// silently.
func (m *Model) requestPluginList() tea.Cmd {
	if !m.RemoteMode() {
		return nil
	}
	return func() tea.Msg {
		msg, err := ipc.NewMessage(ipc.MsgPluginListReq, ipc.PluginListReqPayload{})
		if err != nil {
			log.Printf("plugin list: encode: %v", err)
			return nil
		}
		m.client.Send(msg)
		return nil
	}
}

//

// it is a daemon that told us nothing. Adopting it would grey out every plugin
// at once — the silent failure this change exists to remove.
func (m *Model) applyPluginList(resp ipc.PluginListRespPayload) tea.Cmd {
	if len(resp.Plugins) == 0 || m.pluginRegistry == nil {
		return nil
	}
	avail := make(map[string]bool, len(resp.Plugins))
	for _, p := range resp.Plugins {
		avail[p.Name] = p.Available
	}
	m.pluginRegistry.SetAvailability(avail)
	return nil
}
```

```go
// RecentCWDsPath returns the file storing the last-used working directories
// offered as a quick pick in the pane setup dialog. TUI-owned, single writer.
//
// dest scopes the file to one remote destination. Empty — the local case —
// keeps the historical name exactly, so existing installs need no migration.
// Without the scoping, one flat list mixed laptop and server directories: after
// a remote session the local picker offered paths that exist only on the server,
// and vice versa.
func RecentCWDsPath(dest string) string {
	if dest == "" {
		return filepath.Join(QuilDir(), "recent-cwds.json")
	}
	return filepath.Join(QuilDir(), "recent-cwds-"+destFileKey(dest)+".json")
}

// destFileKey turns an ssh destination into a safe, stable filename component.
//
// The destination is user input that reaches a path, so every character outside
// [A-Za-z0-9._-] is replaced rather than escaped — "../../etc/passwd" and
// "host:22" must both produce an ordinary basename. Collapsing alone is not
// enough: "a/b" and "a-b" would then share a file, so a short digest of the
// ORIGINAL string is appended and is what actually keeps destinations distinct.
// The readable half is kept only so the file can be recognised by eye.
func destFileKey(dest string) string {
	const maxReadable = 32
	var b strings.Builder
	for _, r := range dest {
		switch {
		case r >= 'A' && r <= 'Z', r >= 'a' && r <= 'z', r >= '0' && r <= '9',
			r == '.', r == '_', r == '-':
			b.WriteRune(r)
		default:
			b.WriteRune('-')
		}
		if b.Len() >= maxReadable {
			break
		}
	}
	sum := sha256.Sum256([]byte(dest))
	return b.String() + "-" + hex.EncodeToString(sum[:4])
}
```

### Decisions made here, and why

**A shared deadline across the whole list, not a budget per path.** Identical to `classifyEntries`: a stat that times out has by definition spent the budget, so every later path sees a non-positive one and is dropped without a syscall. That caps a list of dead mounts at ONE abandoned goroutine rather than one per entry.

**The request is capped daemon-side at `maxDirsExistPaths` (32).** `recentCWDMax` is 5, so this is a hostile-client backstop, not a product limit — the bound that matters is on stat calls a single request can start.

**Its OWN single-flight slot, `dirsChecking` — never shared with `browseScanning`.** An earlier draft shared it on the reasoning that "the two are never in flight together." That is false, and it conflates client-side *interest* with daemon-side *occupancy*: the slot is held for as long as the syscall really runs, not for as long as anyone waits (`browse.go:374-377`). The client gives up after `recentScanTimeout` (8 s); the worker keeps the slot for up to `browseTimeout` (10 s) when a stat parks. So the plan's own fallback design guarantees the collision — `applyExistingDirsTimeout` calls `initSetupBrowser()`, whose whole pre-fill chain would then be rejected with "another directory listing is already running" by the very request that just timed out, and the dialog dead-ends. That is precisely the dead-mount case this machinery exists for. The reverse fails too: an abandoned browse from a previous dialog would make a reopened `Ctrl+N`'s pick list fail instantly. This is the same reasoning that gave `gitDiscovering` its own slot (`discover.go:20-25`) — one guard makes each step fail whenever it follows the other.

**The flow becomes asynchronous, mirroring `applyGitReposPickList`.** `fallbackToRecentOrBrowser` currently either sets `recentCandidates` synchronously or returns `initSetupBrowser()`. It now fires the RPC; the answer either populates the pick list or falls through to the browser. That is the same two-outcome shape the shipped git pick list already has, which is why it is copied rather than invented.

**On timeout or error, fall through to the browser.** The browser always works — it is itself an RPC against the same daemon — so this degrades to "you have to navigate" rather than to a wrong list or a dead dialog.

```go
// maxDirsExistPaths bounds one existence request. recentCWDMax is 5, so this is
// a hostile-client backstop rather than a product limit: what matters is that a
// single request cannot start an unbounded number of blocking stats.
const maxDirsExistPaths = 32

// handleDirsExistReq answers "which of these paths are still directories".
//
// The recent-locations pick list used to answer this in the TUI with os.Stat,
// which reads the machine drawing the UI. Against a remote daemon every server
// path failed that test and the list rendered silently empty — indistinguishable
// from a feature that had never been used.
//
// Its OWN slot, never browseScanning's: this hands over to the browser on
// timeout, and the slot outlives the client's patience (held for as long as the
// syscall really runs, not for as long as anyone waits). Sharing would make the
// handover reject every browse request the timeout it just fired goes on to
// make. Same reasoning as gitDiscovering.
func (d *Daemon) handleDirsExistReq(conn *ipc.Conn, msg *ipc.Message) {
	var req ipc.DirsExistReqPayload
	if err := msg.DecodePayload(&req); err != nil {
		log.Printf("handleDirsExistReq: decode: %v", err)
	}
	if !d.dirsChecking.CompareAndSwap(false, true) {
		respondTo(conn, msg.ID, ipc.MsgDirsExistResp, ipc.DirsExistRespPayload{
			Error: "another existence check is already running",
		})
		return
	}
	go func() {
		defer d.dirsChecking.Store(false)
		respondTo(conn, msg.ID, ipc.MsgDirsExistResp, dirsExistResponse(req))
	}()
}

// dirsExistResponse is the pure half.
//
// ONE deadline is shared by every stat, exactly as classifyEntries shares one
// with the directory read that precedes it. That makes the timeout
// self-propagating: a stat that times out has by definition spent the budget, so
// every later path sees a non-positive one and is dropped without a syscall —
// capping a list of dead mounts at ONE abandoned goroutine rather than one per
// entry.
func dirsExistResponse(req ipc.DirsExistReqPayload) ipc.DirsExistRespPayload {
	if len(req.Paths) > maxDirsExistPaths {
		return ipc.DirsExistRespPayload{Error: "too many paths in one existence check"}
	}
	deadline := time.Now().Add(browseTimeout)
	out := ipc.DirsExistRespPayload{}
	for _, p := range req.Paths {
		if isDir, answered := statIsDirWithin(p, time.Until(deadline)); answered && isDir {
			out.Paths = append(out.Paths, p)
		}
	}
	return out
}
```

## Notes

- **Reference implementation.** `internal/daemon/discover.go` + `internal/tui/discover_client.go` are the shipped, live-confirmed pattern. Every new RPC here copies them.
- **Two deliberate deviations from earlier drafts**, both recorded above with reasons: `KubeCtxRespPayload` reports no error for a missing kubeconfig (the distinction does not exist in `kubediscover`), and `PluginInfo` carries no `Homepage` (the local definition already supplies it).
- **RD-024 is two tasks, not one.** The per-target file and the daemon-side existence check each close half of it; either alone leaves the list wrong in remote mode.
- **Residuals — all three get a registry line in Task 5, none gets code here.** Naming them is the point: an undocumented residual reads as a claim that nothing is left.
  1. **Plugin *definitions* are still local.** Only availability crosses the wire, so a plugin the server defines and the laptop does not cannot be offered at all.
  2. **Plugin availability is a daemon-lifetime cache.** `DetectAvailability` runs at daemon start and on plugin reload only, so a tool installed on the server mid-session stays greyed until one of those happens. Fixing it means re-detecting on request, which means removing `Registry.Get`'s pointer escape first — detection writes `p.Command.Cmd` under the write lock while every caller reads that field outside any lock, so today's race is latent and re-detecting on every `Ctrl+N` would make it live.
  3. **`buildPaletteCommands` still calls `os.UserHomeDir()`** (`palette.go:250`) to `~`-abbreviate pane CWDs, so in remote mode a server path is shortened against the laptop's home wherever the prefixes happen to coincide. Display-only and outside the create-pane path, which is why it is not in this plan's scope — but it survives the "no surface reads the laptop's disk to describe the server" claim, so the claim must be worded to exclude it.
