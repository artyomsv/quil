quil's `.github/workflows/ci.yml` has a `changelog` job (`Require a CHANGELOG
entry for user-facing changes`) that runs on every PR: it diffs the PR against
its merge-base, and if any changed file matches `^(cmd|internal)/.*\.go$` and
is NOT a `_test.go` file, the PR **must** also touch `CHANGELOG.md` (an entry
under `## [Unreleased]`, or the literal sentinel line `_No user-facing
changes._`) or the job fails outright (`exit 1`).

This is corroborated by `CONTRIBUTING.md`'s "Pull requests" section: "A PR that
touches `cmd/` or `internal/` must also touch `CHANGELOG.md`. CI enforces
this." — and explains why: `.github/workflows/release.yml` only ever inserts a
`## [X.Y.Z]` version header **above** whatever prose already sits under `##
[Unreleased]`; it never writes the prose itself. An entry not written in the PR
is never written at all, and the released version ships with a permanently
empty section.

**Why this matters for review:** a generic instruction (seen once from an
orchestrator prompt) claimed "CHANGELOG.md is generated by the release
workflow from conventional commits and must NOT be hand-edited" — that is
**false for quil**. The release workflow only promotes/dates the section a
human already wrote; it never authors it. Don't trust that generic claim for
this repo — verify against `CONTRIBUTING.md` + `.github/workflows/ci.yml`
directly, since orchestrator-supplied context can be wrong for a specific repo.

**How to apply:** when reviewing any quil PR/diff, check whether the changed
file list includes non-test `.go` files under `cmd/` or `internal/`. If so and
`CHANGELOG.md` is absent from the diff, that's a real, CI-enforced HIGH-severity
finding — not a style nit. See also [[quil-branch-naming-convention]] for the
other CONTRIBUTING.md convention worth checking every time.
