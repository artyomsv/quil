---
headline: Double-click a word, triple-click a sentence; clean copies
---

- **Double-clicking a word in a pane or in the notes editor selects it.** Paths and URLs stay whole (`./cmd/quil/main.go`), brackets, quotes and separators end a word, and a trailing `.`/`,`/`:` is left out. Triple-clicking selects the whole sentence, following it across the rows it wrapped onto; `3.14` and `v1.75.0` do not end a sentence, and a reply's leading `•` is left out. Right-click copies it as before.
- **Copying a paragraph an app wrapped no longer pastes one line per screen row.** Claude Code and other full-screen tools wrap long text themselves and indent the continuation, so every row used to come out as its own line. A row now joins the next one, with a single space and without the indent, when the next row's first word would not have fitted in the space left on it — the same test the app used when it broke the line there. Blank lines, list items (`-`, `*`, `1.`) and short lines keep their line breaks. Codex, which wraps right up to the last column and indents the next row, joins the same way. The margin every copied line shares (Claude Code and Codex indent a reply by two spaces) is removed; deeper indentation is kept, and a reply's leading `•` marker stays in the copy.
- **Copied CJK text and emoji no longer gain a space after every character.** `abc你好def` copied as `abc你 好 def`: the empty second cell of each wide glyph was written out as a space.
- **Pasting with the notes editor open goes to the side that has focus.** A terminal's own `Ctrl+V` always pasted into the editor, even while the pane on the left had focus; it now reaches the pane like every other key does.
- **`Ctrl+U` and `Ctrl+K` work in the notes editor.** `Ctrl+U` deletes from the cursor back to the start of the line, so pressed at the end of a line it clears it; `Ctrl+K` deletes to the end. Both did nothing before, and the only way to empty a line was the undocumented `Ctrl+Y`, which removes the line itself. All three are now listed under Notes editor in `docs/keybindings.md`.
- **A multi-line paste into the notes editor keeps its line breaks.** Windows Terminal sends each newline in a paste as a bare carriage return, and the editor deleted carriage returns, so the whole paste became ONE line — and `Ctrl+U` at its end then emptied all of it. A bare CR now counts as a line break (and CRLF as one break, not two), in the notes, TOML and template editors alike.
