# Remote Transport

Extracted verbatim from `.claude/CLAUDE.md`. Loaded only when the files above are in play.

## Transport layer

### `internal/transport/`

Dialer backends behind `ipc.DialFunc` (`func(context.Context) (net.Conn, error)`, consumed by `ipc.NewClientWithDialer`). `Local(socketPath)` is the ordinary Unix-socket dial; `SSH(dest, SSHOptions)` runs `ssh -T <opts> <dest> "quil --stdio"` and wraps the child's pipes in `stdioConn` (`stdioconn.go`), a `net.Conn` over `exec.Cmd`.

**The deadline is implemented in the adapter, not by the OS** — Windows `os.Pipe` handles are non-overlapped so `SetReadDeadline` fails on them; a pump goroutine feeds `readCh` and `Read` selects over it with a timer, yielding `os.ErrDeadlineExceeded` (which satisfies `net.Error` with `Timeout()==true`, so `ipc.handshake`'s existing timeout path is unchanged). `stdioConn` requires a **single reader** — concurrent `Read`s race on the `held` remainder — which matches `ipc.Conn.Receive`'s existing contract (`server.go:265`); widening the lock to cover the blocking receive would deadlock `SetReadDeadline`.

**`pump` owns `r` and closes it on its way out; `Close` deliberately does not touch it** — same non-overlapped-handle property: a parked `ReadFile` cannot be cancelled, so `internal/poll.FD.Close` blocks on its reference and deadlocks against the pump, while the kill that would end the read sits BELOW the close that never returns (reproduced as a 3-in-8 whole-package hang on native Windows, goroutine dump in the RD-017 commit). Reordering `Close` to kill first is NOT the fix: it waits for a natural exit on purpose, because `Kill` is `TerminateProcess(handle, 1)` on Windows and would overwrite the 127/126 statuses `remoteinstall` detection reads. The trade is that `Close` no longer force-unparks the read — real conns EOF when the kill lands, but a cmd-less conn whose write end is held open elsewhere keeps the pump alive until that holder lets go. `SetWriteDeadline` honestly returns `os.ErrNoDeadline`. `dest` is passed to ssh **verbatim** (second-to-last arg) so `~/.ssh/config` `Host` aliases keep their HostName/Port/User/ProxyJump; `forcedSSHOptions` disables agent/X11/port forwarding + `PermitLocalCommand` for this connection; `StrictHostKeyChecking`, `ProxyCommand`/`ProxyJump`, `ControlMaster` and `IdentityFile` are deliberately NOT forced (the user's config owns them). `livenessSSHOptions` (`ServerAliveInterval=15`/`CountMax=3`) plus a forced `ConnectTimeout` (`SSHOptions.ConnectTimeout`, default `DefaultConnectTimeout`=15s via `connectTimeoutSecs`, which floors at 1 because OpenSSH reads `ConnectTimeout=0` as NO timeout) bound both ends of the connection's life — the dial runs before `tea.NewProgram`, so an unbounded connect has no UI to be interrupted from.

**`LinkStatus`/`(*stdioConn).LinkErr()` is the load-bearing correctness seam**: `exec.Cmd.Start` succeeds as soon as the ssh BINARY launches, long before it resolves the host or authenticates, so the dial CANNOT fail for network reasons and `main.go`'s "cannot connect" branch only catches spawn-level failures. Every network failure instead surfaces later as a failed handshake read, indistinguishable from an old daemon — which is why `version_gate.go`'s remote arm calls `remoteLinkError()` (backed by the `remoteLinkErrFn` seam that `launchTUI` installs from the dialer via a type assertion) BEFORE reporting a version mismatch, and why `LinkErr` prefers the captured ssh stderr over the raw pipe error. `SSHOptions.Batch` adds `BatchMode=yes` and captures stderr into a `lockedBuffer` for the error message — used by non-interactive dials; the first TUI dial runs non-batch so ssh can prompt for a host-key fingerprint or passphrase before Bubble Tea takes the terminal. That buffer is capped at `stderrBufCap` (64 KiB, **tail**-kept, copy-before-`Reset` because `Bytes()` aliases the storage `Reset` rewinds; the returned `n` stays the inner count or `io.Copy` retries forever) — a successful batch reconnect holds its conn for the whole session and ssh multiplexes the remote command's fd 2 onto that stream, so the writer is remote-influenced and unbounded growth was reachable. `SSHOptions.StderrSink` tees the same stream **sanitized** into `quil.log`: `RedirectStderr` is a no-op on a batch dial (no `switchWriter` on that path), so without it post-reconnect diagnostics vanish exactly when a flapping link needs diagnosing. The buffer keeps RAW bytes (`LinkErr` sanitizes on read) but the sink gets `terminalSanitizer`, because the log is rendered by the F1 viewer — the batch arm never had that filter, so it had to be added rather than assumed. `bestEffort` wraps the sink since `io.MultiWriter` aborts at the first error and a failed log write would otherwise silence `errBuf` too.

**The sink is `cmd/quil`'s `sshStderrLogger`, never the log writer directly**: `terminalSanitizer` deliberately PRESERVES `\n`, so raw bytes would land at column 0 and a remote could emit a line byte-identical to a genuine slog record (and a chunk not ending in `\n` glues the next real record onto it) — the framer accumulates, splits on `\n`, and emits each line through `log.Printf`'s `%q`. It also carries a session-length `sshStderrBudget` (256 KiB), because the rotating writer keeps only `max_files` archives and an unbounded remote would roll the whole set, evicting every other record. `lockedBuffer.buf` is a NAMED field, never embedded — embedding promotes `bytes.Buffer.ReadFrom`, which makes `io.Copy` take its `ReaderFrom` fast path and bypass both the mutex and the cap; the trim fires at **2×** the cap so a remote pacing one byte at a time cannot force a 64 KiB alloc+copy per byte.

**`ctx` bounds the DIAL, not the connection** — `SSH()` builds the child via the `startCommand` package var (`exec.Command`, injectable so a test can substitute a helper; ssh's own argv is passed to the binary, so `SSHPath` alone is not a usable seam) and checks `ctx.Err()` before the PATH lookup, NOT `exec.CommandContext`. The conn owns the child and releases it in `Close`; the documented `ipc.DialFunc` contract says so, because the reconnect loop dials under a per-attempt timeout with `defer cancel()` and `CommandContext` would kill each session at the moment the dial returned it. `run.go`'s `RunSSH` deliberately keeps `CommandContext` — a one-shot remote command IS bounded by its context.

**Non-batch stderr is runtime-swappable** (`stderrsink.go`): `switchWriter` (mutex, nil sink discards and reports a full write, because exec's copier goroutine outlives the TUI's log handle and a short count would make it retry forever) sits under the existing `terminalSanitizer`, and `(*stdioConn).RedirectStderr` — reached through the exported `StderrRedirector` interface, asserted in `dialRemote` beside `LinkStatus` — moves the sink to `quil.log` at `tea.NewProgram` (`redirectRemoteStderr` in `remote.go`, fed the rotating writer `launchTUI` already holds; reopening the file would put two writers on one rotating log). ssh keeps that fd for the whole session and multiplexes the remote command's fd 2 onto it, so a late diagnostic would otherwise land mid-render — the security half was always the sanitizer, this is the cosmetic half

## Remote mode wiring

### Remote mode (`quil --remote <host>`)

`cmd/quil/remote.go` holds `remoteDest` (written ONCE in `main()` at `main.go:94` via `parseRemoteFlag`, before the subcommand switch at `:103` — so `remoteMode()` is already true when `case "mcp"` dispatches at `:107`; that ordering is load-bearing), `remoteMode()`, `errRemoteMode`, and `exitFn` (swappable `os.Exit` for the guard tests). The TUI dial branches at `main.go:340`: `ipc.NewClientWithDialer(ctx, transport.SSH(remoteDest, transport.SSHOptions{}))` — `Batch=false` so ssh may prompt for a host key or passphrase before `tea.NewProgram` takes the terminal. Server side is `cmd/quil/stdio.go` (`quil --stdio`): dial `config.SocketPath()`, `startDaemon(true)` if absent (**quiet is mandatory — stdout IS the IPC channel**), then bidirectional `io.Copy` with a **buffered-2** done channel so the second goroutine can exit rather than leak. Three local-daemon-lifecycle functions refuse under remote mode because they all resolve `config.SocketPath()`/`PidPath()` internally and would act on the WRONG machine: `startDaemon` (`main.go`, guard is the first statement; every `exitFn(1)` site is followed by `return -1` — `exitFn` is a var so the compiler cannot know it doesn't return, and without the explicit returns execution fell through into the spawn path), `stopDaemonEscalating` (`daemonctl.go:67`), `restartDaemonForUpgrade` (`version_gate.go:215`). `refuseRemoteMCP()` (`mcp.go`) runs at the TOP of `runMCP`, before any dial — NOT covered by the `startDaemon` guard, because `connectToDaemon` returns as soon as `ipc.NewClient(sockPath)` succeeds, so with a local daemon running the bridge would silently attach to the LOCAL daemon with no error at all. `runStatus` resolves `config.SocketPath()`/`daemonPID()`/`config.PidPath()` — all local — so `quil status` is refused under `--remote` at the `main.go` subcommand switch (`:130`) rather than answering confidently about the wrong machine while naming none of it; the refusal points at `ssh <host> quil status`. Serving it over the transport instead is RD-026 (`docs/roadmap/remote-daemon.md` § Work registry)

## Reconnect (Phase 2)

### Remote reconnect (Phase 2, RD-010…RD-016)

`internal/tui/reconnect.go` + the `linkLostMsg`/`redialTickMsg`/`redialResultMsg` arms in `model.go`'s `Update`. `listenForMessages` reports a receive error as **`linkLostMsg` data, not `tea.QuitMsg`** — the two were previously indistinguishable from `ipc.MsgCloseTUI`, which is the daemon deliberately asking the TUI to exit and must never reconnect.

**Generations are what make the whole thing safe, and there are TWO of them because they identify different things.** `Model` is a VALUE type, so every `tea.Cmd` closure holds its own copy of the client it was built with. `Model.clientGen` covers the SINGLE-connection path, where `finishReconnect` swaps `m.client` wholesale and a listen loop from the superseded client stays parked in `Receive` long after its replacement is live; it bumps BEFORE `listenForMessages()` is rebuilt, or the new loop stamps the old number and its own future drop is discarded as stale (a session that reconnects exactly once, then dies silently). `reconnectState.gen` covers ONE DESTINATION's timers and dials, and it had to move off the Model the moment two ladders could climb at once: a shared counter bumped by whichever destination finished discarded the OTHER destination's already-armed `redialTickMsg` and in-flight `redialResultMsg`, leaving it `active` with no timer and a banner that stuck for the session. `handleLinkLost` carries `gen` across a drop for the same reason — a drop does not make the previous connection's in-flight results current again. **A router has no session generation at all**: its `r.in` is one channel for the life of the session, so the `linkLostMsg` arm skips the `clientGen` check entirely when the client is a router (checking it there WAS the bug — any other destination's reconnect bumped the counter and the drop was discarded with no ladder started).

**`canReconnect(dest)` = `redialFns[dest] != nil`, with no `RemoteMode()` conjunct**, and the conjunct is not merely redundant but wrong: `RemoteMode()` answers for the ACTIVE PROJECT, so a background remote host dropping while a local project is on screen would read false and turn a reconnectable drop fatal. A local destination never gets a dialer installed, which is what still makes **a dead local daemon fatal** — its panes died with it and retrying would hide that. `lastDaemon(dest)` is the second half of that decision: quitting is right for a session whose ONLY daemon died and wrong for one of several, so a client holding others keeps running and parks the dead destination with a banner that says the daemon is gone and offers no resume key (there is nothing to resume, and `resumeReconnect` guards on `canReconnect` so pressing it anyway cannot reach a nil `RedialFunc`). `reconnectDelay(attempt, jitter)` is pure (jitter is a parameter so the curve is testable) — 500 ms doubling, 30 s cap, scaled into [50%,100%]; its `d <= 0` guard is load-bearing for a non-obvious reason, since the runtime int64 shift WRAPS NEGATIVE from attempt 36 (exact zero only at 57) and a negative duration handed to `tea.Tick` fires immediately. `freezeInput` sits ahead of `Update`'s type switch as ONE choke point rather than a guard in each of six input branches, so a future input message type is frozen by default; keystrokes are DROPPED not buffered (a key typed at a dead link would land in a live agent session minutes later at a prompt that moved on), and `kb.Quit` is the sole exception. `armReattachReset(dest)` + `resetWorkStateForReattach(dest)` run BEFORE `attachToDest(dest)` and share `eachClientPane` so the two enumerations cannot drift — it covers every tab of every project ON THAT DESTINATION (one attach replays all of them) plus each tab's `overlayPane`, which is a live daemon pane replayed like any other but deliberately OUTSIDE the layout tree, so a `Leaves()`-only walk misses exactly one pane per tab. Both are scoped by dest because only the reconnected daemon replays: sweeping every project would zero the work counters of daemons that never dropped.

**Attach is per destination and idempotent** (`Model.attachAllDests`, ledger in `m.attached map[string]bool`). Every attach replays the daemon's whole ghost buffer, so a second one doubles a pane's scrollback and re-counts the work-state events inside the replay — which is why `finishReconnect` SETS `m.attached[dest]` rather than clearing it, and why attach could not move to dial time in `cmd/quil` (it already has two owners; a third would attach every conn twice). The other reason it cannot move: `AttachPayload` carries `Cols`/`Rows` and the daemon sizes the first PTY from them, while at dial time Bubble Tea has not reported a window size — a fresh daemon would spawn its Shell pane at 0×0. `m.workTickRunning` is deliberately NOT cleared either: the spinner loop is self-stopping, and clearing the flag while a tick is scheduled lets the next hook event start a second loop beside it. `unseen`/`pinnedAttention` survive — they report unread work, not a live turn.

**The listen loop is re-armed by the `linkLostMsg` arm for a router, and by `finishReconnect` for a single connection**, and the asymmetry is load-bearing in both directions. A router's loop stopped only because it delivered a synthesised loss as DATA, and it is the sole reader of every OTHER daemon's messages — leaving it unarmed parks a healthy daemon's output behind a dead one's ladder for as long as the ladder climbs. A single connection's loop died with its client, so re-arming it there means calling `Receive` on a dead conn, which fails instantly: a hot loop. `finishReconnect` therefore re-arms ONLY on the non-router path; arming a second reader of `r.in` would add one goroutine per reconnect.

Client side of the dial is `cmd/quil/remote.go`: `dialRemoteTransport(ctx, cfg, dest, batch, sink)` is the SINGLE dial implementation shared by the startup dial and every redial (the reason `transport.RunSSH` shares `sshArgs` — a second call site assembling its own options is free to drop a forced hardening flag), and `redialRemote(cfg, dest)` sets `Batch=true` because Bubble Tea holds the terminal in raw mode by then so ssh has nowhere to prompt. `dest` is a PARAMETER on all of them, not the process-wide `remoteDest`: one dialer per destination is what gives each host its own `sshStderrLogger` byte budget, so a single flapping host cannot exhaust every other's log allowance.

**`verifyRemoteLink` is the correctness seam, and its absence was a shipped-then-fixed bug**: a dial proves only that ssh's BINARY started, so against an unreachable host every attempt reported success, cleared the banner, reset every pane for a replay that never came (blank panes), and zeroed the reconnect state so `attempt` never passed 1 and the backoff never engaged — it now completes an `MsgVersionReq`/`MsgVersionResp` round-trip (following `daemonAlreadyHealthyWithin`) under `linkVerifyTimeout`=20 s, sized just past the transport's 15 s `ConnectTimeout` because that is what actually ends the read. Banner (`renderReconnectBanner`/`bannerCandidates`) is a compositor overlay over row 0 so it reserves no layout height, degrades through a ladder of shorter forms that EACH keep `ctrl+q` (a single truncated string cut it to `ctr…` at 40 cols, which `minTermWidth` makes reachable), truncates the ssh diagnostic into whatever room is left rather than dropping it whole (a real ssh error runs past 50 chars, so an all-or-nothing fit check hid it at 80 cols), and renders two distinct phases — `nextAt` in the future is a countdown, in the past is `Connecting`, which against a down host lasts a full `ConnectTimeout`. Liveness detection is ssh's `ServerAliveInterval`/`CountMax` (~45 s); `ipc.MsgHeartbeat` remains declared and unsent (registry open question 4, answered).

**A failure whose stderr matches `transport.ClassifyLinkFailure`'s short permanent list PARKS the loop** (`reconnectState.parked`) instead of retrying: every reconnect is a full authentication, and the design's own asymmetry makes permanent failure reachable without an attacker — the startup dial is non-batch so ssh may prompt for a passphrase, every reconnect is batch because Bubble Tea owns the terminal by then, so a passphrase-only key authenticates once at launch and fails `publickey` forever after. A default fail2ban `sshd` jail bans the resulting stream. Parking keeps the banner up (paused, not over) and `reconnectResumeKey` (`r`) resumes WITHOUT resetting `attempt`, so the rate decay is not undone. Matching ssh's prose is a **documented exception** to the exit-code-only rule (`internal/remoteinstall`): ssh answers 255 for every failure of its own so the code carries no signal, and OpenSSH ships no translations for these strings. Unmatched ⇒ **transient**, deliberately — mis-parking a session that would have healed is the worse error. Classification lives in `redialRemote`'s **verify-failure** branch, never the dial-failure branch, where `link` is always nil because `exec.Cmd.Start` succeeds as soon as the ssh binary launches.

**`ClassifyLinkFailure(stderr, established, exitCode)` takes all three signals because the text alone is remote-influenced** — ssh multiplexes the REMOTE command's fd 2 onto its own stderr, and `permission denied` is a string any Unix shell emits, so an ordinary `~/.bashrc` touching an unreadable path would park the session and a compromised remote could do it deliberately. The raw match is unexported (`matchesPermanentMarker`) precisely so no caller can use it alone. Two independent gates make the text attributable to ssh:

**`established`** counts only bytes the pump read, and the pump reads STDOUT, so any byte proves the remote command ran ⇒ ssh authenticated ⇒ an auth marker cannot be ssh's own; **`exitCode == ExitSSHOwnFailure` (255)** because ssh passes the remote command's status through untouched (127/126/…), and when `Close` has to kill a still-live ssh the status is the kill rather than 255 — so a transient drop fails this gate too, which is the safe direction. Both are read AFTER `Close` (it reaps the child, so the status is only final then), the opposite order from `LinkErr`, which `Close` can clear. `TestClassifyLinkFailure_RemoteShellNoiseCannotPark` pins the hazard and both gates; `TestClassifyLinkFailure_EstablishedNeverParks` pins the stronger gate against every marker so a later addition cannot quietly become parkable. The resume key is checked in `Update` **ahead of** `freezeInput`, which has a value receiver and so can neither clear `parked` nor return a mutated Model; `bannerCandidates` checks `parked` before both existing phases, or the stale-past `nextAt` renders `Connecting` at a session where nothing is connecting

## Several daemons from one client

### The router and the connection table (Task 17)

`internal/tui/router.go` multiplexes N daemon connections behind the one
`tui.Client` the Model consumes, and `cmd/quil/dialall.go` builds the table.
**There is no single-connection path in production any more** — `launchTUI`
always constructs a `*Router`, even for a lone local daemon — so the
single-connection branches in `finishReconnect`, `lastDaemon` and the
`linkLostMsg` generation check exist for the Models tests build directly.

**`NewModel`'s first parameter is the `Client` interface and the router is built
BEFORE it**, never installed afterwards and never read back through a closure:
`tea.NewProgram` takes the Model BY VALUE, so a closure over `main`'s copy would
freeze at startup and route every unstamped send to whatever was active at
launch. The running program pushes the active destination the other way, through
`Router.SetActiveDest` via `syncActiveDest()`.

**Liveness is keyed off `r.stop[dest]`, and the conn record deliberately
outlives its pump.** `retire` removes only the stop channel. That is what keeps
`Conn(dest)` non-nil for the destination a redial is about to run for — this
package structurally cannot close a `Client` (Send/Receive by design), so the
dead conn has to survive until `redialCmd` hands it to the dialer in `cmd/quil`,
which closes it. Retiring the whole record leaked one ssh child plus its remote
`quil --stdio` per reconnect. `CloseClient` unwraps the router and releases each
conn for the same reason: `closeClientFn` type-asserts to `*ipc.Client`, so
handing it the `*Router` missed silently and exit closed nothing.

**`Router.Send`'s sole-conn fallback is for the startup window only** — between
launch and the first `workspace_state` there are no projects, so `activeDest()`
is `""` and a remote-only router has no conn under that key. It is gated on
`len(r.conns) == 1` and nothing on the startup path may depend on it: a router
holding local + remote delivered the deliberately-unstamped startup attach to
`conns[""]` alone, so the second daemon was never attached — no workspace state,
no projects, no error. Attach and `requestPluginListFor` both stamp now.

**`[[destinations]]` in `config.toml`** (`name`, `dest`) lists the ADDITIONAL
daemons; `dest` is passed to ssh verbatim like `--remote` and is also the routing
key. `quil --remote <host>` ignores the list entirely — that mode means "drive
that machine" — and keys its own connection by the host rather than `""`, so its
projects, reconnect state and banner key exactly as a mixed session's do.
Background destinations dial CONCURRENTLY in batch mode: three hosts that are all
off then cost one connect timeout rather than three, and batch is what makes the
concurrency safe (interactive dials would interleave host-key prompts on one
terminal). They get `gateExtraVersion`, which has none of `gateVersionCheck`'s
interactive remedies — a background host must never open a blocking dialog, offer
an install, or exit the process — and a refusal lands in the same
"unreachable at launch" branch as a host that is simply off.

**Gap closed:** a destination unreachable at LAUNCH used to have no conn, so no
pump, so nothing ever published a loss for it and its reconnect ladder never
started — reported on stderr at launch, and fixed only by a relaunch. The
launch path now seeds an offline stand-in row for it (`SeedOfflineDest`) and
starts its reconnect ladder itself, through `offlineDestMsg` — a message type
of its own rather than a synthesised `linkLostMsg`, since no listen loop is
running for a destination that never connected in the first place (re-arming
one that already exists would install a second permanent reader of the
router's `r.in`). See `.claude/rules/projects.md`'s "Offline destinations"
section for the client-side mechanism this closes the gap with.

## Remote auto-install

### Remote auto-install (`quil remote setup <dest>`)

`internal/remoteinstall/` + `cmd/quil/remote_setup.go`. The LAPTOP pushes — it downloads the archive for the REMOTE's platform, verifies the checksum locally, and streams it over ssh — so a server with no route to GitHub still provisions, and the installed version matches the TUI by construction. `update.AssetName`/`FindAssets`/`Stager{GOOS,GOARCH}` are already platform-parameterized, so `FetchRelease` stages into a temp dir and repacks via `PackDir` rather than duplicating download/verify/extract; `update.Checker.Release(ctx, tag)` was added because installing "latest" when the TUI is not latest inverts the mismatch it was called to fix.

**Detection is the ssh EXIT CODE, never the string "command not found"** (locale-dependent, and empty on a non-batch dial where stderr went to the terminal): 255 is ssh's own failure, 127 the remote shell not finding the command, 126 finding it and failing to exec. `stdioConn` therefore reaps for status — `reapOnce` guards `cmd.Wait` (both `pump` and `Close` reach it), `Close` **kills BEFORE reaping** (`Once.Do` blocks the second caller, so an unkilled child would hang Close until ssh exited), and `pump` defers `reap` BEFORE `close(readCh)` so LIFO unparks readers first. `LinkErr` is read BEFORE `Close` (Close can clear `pumpErr`) and `ExitCode` AFTER (Close is what makes the status final) — `version_gate.go`'s guard brackets `client.Close()` with exactly that pair, pinned by `TestGateVersionCheck_ReadsExitCodeAfterClose`. `ClassifyExit` treats `Established()` as an OVERRIDE: any byte means quil ran, so a later 127 is a remote crash, not a missing binary.

**Loop guard (`healRemoteRecord`, RD-045/RD-046)**: a wrong-arch binary also reports 127, so without a guard a launch would install → retry → 127 → offer forever; the realistic trigger is `uname -m` disagreeing with userland (64-bit-kernel/32-bit-userland Raspberry Pi OS reports `aarch64` while the loader is armhf), which is also why `PlatformFor` REFUSES unknown arches instead of guessing and `PackDir` checks ELF/Mach-O/MZ magic. **The guard asks the HOST, not the config** — it used to be `alreadyProvisionedFn` = `cfg.RemoteBinary(dest) != ""`, i.e. "a path is recorded" read as "quil is installed there". Those diverge every time a remote binary vanishes behind Quil's back (image rebuilt, home wiped, `~/.local/bin` cleaned, binary moved by an admin, OS reinstalled on the same hostname), and the result was an architecture theory for a host whose arch was always correct, no install offered, and hand-editing `config.toml` as the only way out. The guard now runs the probe and switches on three states: `ExistingPath == ""` ⇒ the record is known-false, clear it and offer the install; `ExistingPath == recorded` ⇒ we ran exactly that path and it still failed, so this IS the wrong-arch case and is what makes the loop terminate (offering forever needs a path that exists, only true after a successful write); `ExistingPath != recorded` ⇒ we ran the wrong path, record the probe's and re-dial, which also covers a hand-installed host that was never recorded. **Positive evidence only**: the record is mutated when the probe ANSWERED, never on a probe error — absence of evidence must not clear it, since a record dropped on a transient failure silently downgrades a working host to bare `quil` on the non-interactive PATH, the exact failure the record prevents (`TestHealRemoteRecord_ProbeError_LeavesRecordUntouched` pins it, mutation-verified). The probe result is handed to `runRemoteSetup` through `setupOptions.probe` so the attach path costs one ssh round trip rather than two; the `quil remote setup` CLI passes nil and probes itself. `RemedyUpgrade` skips the whole reconciliation — quil ran over there, so the binary is fine. Probe and install use DIFFERENT stdin shapes on purpose: the probe rides stdin (`sh -s`, no quoting needed), the installer CANNOT (the archive is there) so it is passed as an `sh -c` argument — ssh joins command args with spaces and quotes nothing, hence `ShellSingleQuote` on the script, dir and hash, plus `scriptArg0` as `$0` or the dir would become `$0`. The probe ALWAYS exits 0 (its exit code must mean ssh, not a finding) and looks for an existing install by ABSOLUTE path before `command -v`, since the non-interactive shell that motivates the whole feature cannot see `~/.local/bin`. Target selection never sudos: in-place only when the existing dir is writable, else `~/.local/bin` + a reported `Shadowed`. The resolved path is persisted as `[remote.hosts.<dest>] binary` and consumed by `remoteSSHOptions(cfg)` → `SSHOptions.RemoteCommand`. `transport.RunSSH` shares `sshArgs` with the dial so hardening + the leading-`-` destination rejection cannot diverge (a second call site building its own argv would drop the `-oProxyCommand=` guard). Windows remotes are OUT: no `sh`/`uname`, `.zip` archives, and a running `.exe` cannot be overwritten (`mv -f` over a running ELF works because the process keeps its inode) — fresh install would be easy, upgrade is the hard half. Scripts are `go:embed`ed and MUST be LF (`.gitattributes` `*.sh text eol=lf`); `TestEmbeddedScripts_AreLF` is a regression guard for a bug this repo has already shipped, and the script tests EXECUTE against busybox so a GNU-only flag fails in CI rather than on a user's Alpine box
