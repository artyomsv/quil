# Plugins

Extracted verbatim from `.claude/CLAUDE.md`. Loaded only when the files above are in play.

## Plugin system

### Plugin system

`internal/plugin/` — pane types defined via `PanePlugin` struct. Terminal and `terminal-wide` ("Terminal (keeps content on squeeze)" — same shell detection with `Display.WideCanvas = true`, so pane squeezes never cut content at the cost of window-width formatting while narrow) are Go built-ins in `builtin.go`; claude-code, ssh, stripe are embedded TOML defaults in `defaults/*.toml` (written to `~/.quil/plugins/` on first run via `EnsureDefaultPlugins`). User TOML plugins override defaults. `schema_version` field in `[plugin]` section tracks TOML schema — `EnsureDefaultPlugins` detects stale files (user version < embedded) and returns `[]StalePlugin` for the TUI migration dialog instead of silently overwriting. Bump `schema_version` in embedded defaults when adding new fields or changing defaults. `Registry` manages loading, detection, and lookup. Plugins define `FormFields` + `ArgTemplate` for instance creation forms. `GhostBuffer` bool controls per-plugin ghost buffer persistence. `[[idle_handlers]]` TOML section for context-aware idle notifications (parallel to `[[error_handlers]]`). Optional `path` field in `[command]` for explicit binary location (bypasses PATH lookup). 3-tier detection: path override → `exec.LookPath` → `searchBinary` fallback.

**Pane setup dialog opt-ins**: `prompts_cwd = true` under `[command]` opens a directory browser at pane creation (pre-filled from active pane's OSC 7 CWD); `[[command.toggles]]` array-of-tables (fields: `name`, `label`, `args_when_on`, `default`, `group`) renders one control per toggle — enabled toggles' args are appended to `InstanceArgs`. Toggles with the same non-empty `group` value are mutually exclusive (rendered as radio buttons; enabling one disables the other group members; "none selected" is also valid). Empty `group` = independent checkbox; `raw_keys = [...]` declares keys that bypass Quil's global shortcut layer and are forwarded directly to the PTY (no built-in plugin currently opts in — Tab and Shift+Tab reach the PTY naturally because pane navigation moved to `Alt+Arrow`. The mechanism stays available for future plugins that need to override some other global shortcut.). claude-code uses `prompts_cwd` + `[[command.toggles]]` with a `permission_mode` group to offer a mutually-exclusive choice between `--dangerously-skip-permissions` and the safer `--enable-auto-mode` (with "neither" as a valid option). The TUI side lives in `internal/tui/dialog.go` (`enterSetupOrSplit`, `loadBrowseDir`, `handleCreatePaneSetupKey`, `renderCreatePaneSetupDialog`, `validateAndNormalizeCWD`) and `internal/tui/model.go` (`tryPluginRawKey`). See `docs/plugin-reference.md` for the full reference

### Plugin instances

`internal/tui/instances.go` — `InstanceStore` (map[pluginName][]SavedInstance) persisted to `~/.quil/instances.json`. `BuildArgs` expands `{placeholder}` templates from form field values

### Pane type fields

`Pane.Type` (plugin name, default "terminal"), `Pane.PluginState` (scraped key-values), `Pane.InstanceName`, `Pane.InstanceArgs`. All persisted in workspace JSON, backward compatible (missing `type` → "terminal"). `Pane.Muted` (persisted, `Alt+M` via `mute_pane`) suppresses notification events. `Pane.Eager` (persisted, `Alt+Shift+E` via `toggle_eager`) makes the pane respawn immediately on daemon restart instead of being deferred; tabs containing an eager pane show a `●` marker in the tab bar (rendered via `tabLabel`/`eagerTabMarker` constant)

### Plugin schema migration

`dialogPluginMigration` shown on startup when `EnsureDefaultPlugins` detects plugins whose `schema_version` < embedded default. Full-screen split view (`internal/tui/migration.go`): editable user config on the left, read-only new default on the right (both `TextEditor` with TOML highlighting). Tab bar for multiple stale plugins. Blocks until all resolved — Esc is a no-op, only Enter (save merged), A (accept default), or Ctrl+Q (quit) exit. On save: validates TOML syntax + `schema_version >= required`, writes to disk, reloads plugin registry. `StalePlugin` struct in `internal/plugin/plugin.go` carries user data + default data from `EnsureDefaultPlugins`. `ParseSchemaVersion` (exported) extracts `[plugin].schema_version` from TOML bytes

## Tool plugins

### Lazygit integration

`internal/gitdiscover/` — pure repo discovery (enclosing repo + one-level sub-repos, canonical paths via `filepath.EvalSymlinks`, cap 10). `discover = "git"` plugin opt-in switches the setup-dialog CWD step from the plain browser to a candidate list + "Browse…" fallback (only meaningful with `prompts_cwd = true`; unknown values fail plugin load). Per-tab Alt+G overlay (`toggle_lazygit` keybinding): `Pane.Overlay` bool (PluginMu-guarded) marks the pane as ephemeral — excluded from disk snapshots and ghost saves; TUI `TabModel.overlayPane` sits outside the layout tree; state machine in `internal/tui/overlay.go` (visible→hide; candidates from active pane CWD; match→show instantly with state preserved; multiple→`dialogGitRepoPick` picker; create/replace gated on binary availability). Overlay panes are muted at creation, keyboard-only (mouse swallowed), and auto-destroyed by the daemon on process exit (spec: `q` quits → `onPaneExit` checks `Overlay` → `cleanupPaneArtifacts` + `DestroyPane` + `broadcastState`; TUI reconciliation clears the slot; next Alt+G creates fresh). Allow-list while overlay visible: Alt+G hide, Ctrl+Q quit, redraw, Alt+1..9 tab switch — everything else (including Esc) reaches lazygit.

**An overlay this client just CREATED shows the boot indicator, and being outside the layout tree is what cost it one.** A pane created in the tree while the TUI runs is marked `preparing` (the `len(existingTabs) > 0` arm of `rebuildTabs`), which is what puts the spinner and the boot label on screen while the child starts. `reconcileOverlayPane` built its pane with a bare `NewPaneModel`, so lazygit scanning a large repository — or hunk computing a diff — was an empty FULL-TAB rectangle for its entire startup, with nothing to say whether anything was happening. It is gated on `pendingOverlayShow[tab.ID]`, i.e. exactly "this client's Alt+G/Alt+D created this": an overlay adopted on a plain REATTACH is a tool that has been running for hours, and it is hidden by default there anyway. Marking it is only half the fix, because two other places assume the layout tree: `spinnerTargetPane` (which REPLACED `leafByID`) resolves a tick's pane across tree leaves AND `tab.overlayPane`, or the chain dies on its first message and the indicator renders one frozen frame — and that same resolver is what the chain-START guard uses, since a stacked chain stopped being invisible the moment ticks began landing. The overlay branch of `handlePaneOutput` settles via `restoreSettled()` like the tree branch rather than clearing on the FIRST byte: lazygit's opening frames set up the terminal and clear the screen well before they paint, so a first-byte clear took the indicator down over a still-blank pane. It clears `resuming` as well as `preparing` — no overlay path arms `resuming` today, so the wider condition is inert, and a narrower one would silently leave the next path that does to the 30 s safety cap.

**Alt+G to HIDE is a different path from `q` to QUIT, and until this was bounded that difference cost real memory.** Hiding only pulls the pane out of `TabModel.overlayPane` — it never told the daemon to destroy anything — so a lazygit opened once per tab ran for the life of that tab regardless of how long it sat hidden (measured: 7 live overlays in one real session, ~116 MB RSS each). `internal/daemon/overlay.go` now bounds both dimensions independently. `sweepIdleOverlays`, riding the existing 1 s `idleChecker` tick, destroys an overlay hidden past `[overlay] idle_timeout_minutes` (default 5, `0` disables). `enforceOverlayCap` bounds total live overlays across ALL tabs at `[overlay] max_live` (default 5, `0` disables) — checked at CREATION (`createPaneAt`), not on a timer, so opening one past the cap is instant and deterministic rather than "eventually reclaimed." **Visibility is REPORTED by the TUI (`UpdatePanePayload.OverlayVisible *bool`), never inferred from pane activity**: an idle lazygit emits nothing whether it is on screen or hidden, so "no output" and "not visible" are indistinguishable from the daemon's side, and an activity-based rule would evict the overlay the user is actively reading. **That report is a CLAIM by one client, not a daemon-wide fact.** `attachedConns` maps each attached conn to the set of overlay panes that client has on screen, and an overlay counts as hidden only when NO client claims it (`overlayClaimed`). A single field was last-writer-wins: with two TUIs on one daemon, the second one merely switching tabs reported an overlay hidden while the first had it open, and the sweep destroyed that lazygit five minutes later — mid-rebase, since lazygit mutates `.git`. No attacker needed; the second TUI adopts the overlay with `overlayVisible=false` and reports the moment it navigates. A conn that never sent `MsgAttach` (an MCP bridge) can move the timestamps but holds no durable claim, so it cannot pin an overlay it is not displaying. Claims are dropped in `cleanupPaneArtifacts` — the choke point every destruction path already owes — or a destroyed overlay's id stays in a live client's set for the life of the daemon.

A detached session therefore needs no special case: a departed client's claims leave with it, so "no clients attached" is the strongest form of "nothing claims this" and `hideUnclaimedOverlays` (run on EVERY disconnect) stamps the rest — which is what lets the idle timer run down while the user is away rather than only after the next attach notices the overlay is stale. Eviction under the cap is LEAST RECENTLY **SHOWN**, not oldest-created: a FIFO policy would repeatedly evict the overlay the user reopens constantly, purely because it happened to be the first one ever created.

**Truth is reported by every path that changes what is ON SCREEN, and `overlayOnScreen` is the single definition of that** — the tab must be its project's active tab AND that project must be the active one. Five callers share `overlayTruthTransitionCmd`: `switchTab`, `jumpToPane`, `jumpToNextBlocked`, `switchProject`, and `applyWorkspaceState`'s adoption of a daemon-side active-tab change (MCP `switch_tab`, a new tab, a tab destroy, a second client). The last two were missing, each reintroducing the original leak through a different door: a background PROJECT's overlay stayed marked visible for the life of the daemon, and a daemon-side tab move left both drift directions open. The broadcast arm reports only when a project's active tab actually MOVED — the git ticker alone broadcasts every 5 s.

**An eviction pass emits ONE broadcast**, not one per pane (`publishOverlayEvictions`), and a visibility-only `MsgUpdatePane` emits none at all: neither overlay timestamp is on the wire or in the snapshot (`includeOverlays=false`), so that frame carried zero changed state on a path that now fires on every tab switch. Both are the 2026-08-09 critical-queue shape. `setOverlayPolicy` clamps to `[0, 525600]` minutes at both entry points (config seed and IPC push) because `time.Duration(n) * time.Minute` wraps int64 above ~307,445,734 — `307445735` (≈585 years, an "effectively never" value) wrapped to about 26 SECONDS.

### hunk integration

`defaults/hunk.toml` — review-first diff viewer, second consumer of the overlay slot (`toggle_hunk`, default `alt+d` — NOT `alt+h`, which `tui-rendering.md` reserves as a PTY passthrough alongside `alt+v`; `TestHandleOverlayKey_AltH_ReachesThePTY` pins that). Reuses `discover = "git"` and every daemon-side overlay mechanism unchanged (idle sweep, live cap, per-client visibility claims are all pane-keyed). Two things are specific to it and both are load-bearing:

**The subcommand lives in `[command] args = ["diff"]` and the plugin must stay TOGGLE-FREE.** `resolveSpawnArgs` REPLACES base args with `InstanceArgs` whenever a pane has any, and `submitSetupDialog` builds `InstanceArgs` out of enabled toggles — so one added toggle spawns `hunk --whatever`, silently dropping `diff` and leaving the pane on a help screen. Same reason `createOverlay` sends NO `InstanceArgs` for hunk (`overlayInstanceArgs`): lazygit's `--path <repo>` has no hunk equivalent, and copying that shape would replace the subcommand. Hunk is scoped by CWD alone. `TestDefaultHunk_SpawnsTheDiffSubcommand` asserts the args AND the absence of toggles together, because either alone is satisfiable while the pane stays broken.

**ONE overlay slot per tab, so every step of the state machine keys on the PLUGIN, not on the existence of an overlay** (`handleToggleOverlay(pluginName)` / `resolveOverlay(tab, candidates, pluginName)` / `TabModel.overlayRuns(pluginName)`). Four decisions change meaning: the hide branch (the other tool's key must SWAP, not read as "toggle off" — else the user presses it twice to get anywhere), step 3's show-anyway fallback (showing lazygit in answer to the hunk key answers a question nobody asked), step 4's candidate match (right repo + wrong tool must be replaced), and both availability gates (they share a slot, not an installation). `Pane.Type` is daemon-authoritative via `syncPaneMeta`, so the check reads what is RUNNING rather than what this client asked for. Step 2 must resolve the CWD from `treeActivePaneModel`, never `ActivePaneModel` — the latter returns the OVERLAY when one is visible, which is now reachable there, and a swap would resolve against the outgoing tool's repo.

**The destroy and the create of a replace leave in ONE `tea.Cmd`, destroy first — never as two siblings of a `tea.Batch`.** Batch runs its children on separate goroutines and orders nothing (the same property behind the keystroke-transposition bug), and the daemon runs `enforceOverlayCap` at CREATE time: a create that wins the race is counted against a cap that still includes the outgoing overlay, so the pass evicts the least-recently-**shown** overlay to make room. The outgoing one was just on screen and sorts newest, so the victim is a DIFFERENT tab's overlay — typically a lazygit left running elsewhere, which mutates `.git` and may be mid-rebase. The shared slot is what promoted this from rare to routine: the replace path used to run only when the resolved repo differed, and now every tool swap goes through it. `TestCreateOverlay_DestroyAndCreateShareOneCmd` pins it STRUCTURALLY (walking the cmd tree leaf by leaf), because a test that only reads `fake.sent` walks a batch sequentially and sees the right order whether or not it is guaranteed.

**The requesting plugin rides the discovery round trip in `repoScanState.plugin`, and the picker's in `Model.repoPickPlugin`** — discovery is a daemon RPC and the picker outlives the keypress, so in both cases the key is long gone by commit time. Recovering it from `tab.overlayPane` is the obvious shortcut and is exactly wrong: during a swap that slot still holds the OUTGOING tool. `renderGitRepoPickDialog` titles itself from `repoPickPlugin` for the same reason — a picker that always said "lazygit" would be lying on the one screen where the user commits to a repository. Both toggles are on `handleOverlayKey`'s allow-list (a key left off is delivered to the running tool as PTY input), and neither is in `notesKeyExempt`, deliberately, matching the original lazygit decision.

### k9s integration

`internal/kubediscover/` — pure kube-context discovery (parses kubeconfig YAML from `KUBECONFIG` (OS-list-separated) → `~/.kube/config`; reads only context names + default namespaces + current-context, never credentials; follows symlinks; sanitizes control chars from names/namespaces; every failure degrades to empty). New dependency `gopkg.in/yaml.v3`. `discover = "kube"` plugin opt-in (third valid value alongside `""`/`"git"`) adds a kube-context pick field to the setup dialog (CWD-independent, works with `prompts_cwd = false`): row 0 = "Default context" (no flag), rows 1..N = contexts (current marked `●`), capped at `maxKubeContexts = 50`; selecting a named context injects `--context <name>` into `InstanceArgs` via `submitSetupDialog`. Field plumbing in `internal/tui/dialog.go` (`setupFieldKind`/`setupFieldCount` insert a "kube" field, `handleSetupKubeKey`, render branch). The `k9s` built-in plugin (`defaults/k9s.toml`) opens k9s as a normal pane (not an overlay), `rerun` strategy, ghost buffer off. Uninstalled tool plugins are now shown greyed in Ctrl+N (not hidden) with a `homepage` link (`[plugin] homepage` field) and blocked from selection; the create-pane dialog auto-sizes its width to its content (`maxContentLineWidth`).

### lazysql integration

`defaults/lazysql.toml` — database TUI (MySQL/PostgreSQL/SQLite/MSSQL) as a normal pane. Connection-scoped, not directory-scoped: `prompts_cwd = false`, no `discover`, `rerun` strategy, ghost buffer off, one `--read-only` toggle.

**Deliberately no Quil-side connection picker** — lazysql's only launch arg is a full DSN (with credentials), which must never reach argv/`workspace.json`/MCP logs; connection selection + credentials stay in lazysql's own manager (`${env:}` substitution). TOML-only, no Go code; binary gating + greyed-when-missing come free.
