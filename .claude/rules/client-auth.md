# Client authentication and rights

User guide: `docs/security.md`. Decision record: ADR-34 in `docs/architecture.md`.

**One check point.** `admitRequest` (`daemon/rights.go`) runs `clientauth.Allows` first in `handleMessage`, after the pre-login branch. Never add a second rights check inside a handler; add the type to the class table instead. An unclassified type is admin (fail closed), and `clientauth/sweep_test.go` parses `internal/ipc` so a new `Msg*` constant without a class fails CI; `TestClassTable_MatchesSpec` pins the WHOLE table, so moving a type to a weaker class fails too. Daemon→client types are listed EXPLICITLY there. A refused id-bearing request gets `error refused` INSTEAD of its usual response — on a LOCAL conn only once that conn has said hello (`replyError`'s proto gate; a conn that never did keeps its silence) — and an id-less one is dropped; the refusal audit key of an unclassified type is the constant `unclassified`, so invented type names cannot flood `audit.log`. A TCP conn may park at most `maxParkedPerConn` (4) goroutines (`admitParked`, `parksGoroutine`): `watch_notifications`, `wait_task`, and every handler that answers from its own worker with no daemon-wide single-flight slot — `sandbox_cap_req` (waits for the Docker probe), `note_get` and `note_set` (wait for the pane's note lock). The waits are counted on the conn's `AuthState`, the watch by its registered watcher (a watch that only replaces the conn's own passes at the cap), and every arm releases its slot before it answers. A worker keeps the request's ID, never the `*ipc.Message`: a padded payload would otherwise be held for the whole wait. A NEW handler that spawns a per-request worker either takes a single-flight slot or joins `parksGoroutine`. The per-conn count alone is not a bound — a new conn starts empty — so a worker must also END with its conn: a `sandbox_cap_req` waits on `connContext(conn)`. EVERY caller of `sandboxCap.get` only waits — the one that finds no probe running included, so the plugin catalog keeps its 2 s budget — while the single shared probe runs on its own goroutine from `context.Background` (cut short by one caller, it would cache "docker not available" for every client for 30 s). `closeAuth` waits for the revoke/expiry close workers (`authService.closeWG`) before closing `audit.log`, and sets `closeClosed` first under `closeMu`, so a revoke handler still running after the conn drain timed out starts none. The local socket is not capped.

**Pre-login.** An unauthenticated TCP conn (`Conn.Auth() == nil` — the ONLY nil case; local conns and a nil `*Conn` read full) reaches `handlePreLogin` only. `wantsFrame` sends it no broadcast; `Receive` caps its frame at 4 KiB before allocating; `acceptTCP` closes the 9th pending conn at accept. The login timer is a `time.AfterFunc` per step, never a read deadline (`markDead` owns that). The CAS out of `loginPending`/`loginProofPending` is what clears it; the timer and the CAS are deliberately redundant. A refused conn stays registered in `loginRefusing` until it disconnects, and `handlePreLogin` never closes a conn itself — a frame arriving during the 1 s refusal flush is ignored, not allowed to cut the flush short. The step timeout and backoff base/cap are package vars copied into `authService` by `initAuth`; tests set them BEFORE the harness.

**The proof.** `AuthMessage` bytes are exact; known-answer vectors in `clientauth/scram_test.go` pin the chain — do not "fix" a vector to make a test pass. An unknown token id is challenged and verified against a dummy key, and the proof is checked BEFORE expiry, so expiry is never revealed to someone without the key. Every failure is `error refused` with one reason, carrying the hello's ID (the client reads the login by that ID; any other ID reaches the user as a bare EOF): `login required` before the challenge, `token refused` after it, `login timeout` for a step timeout, `too large` for an oversized proof frame (`onTCPRejected`). An oversized FIRST frame has no ID to answer and is closed with no frame. Each refusal is sent directly, flushed 1 s, then closed. Backoff (`min(250ms*2^(n-1), 2s)`) runs AFTER the proof frame, never before the first frame. Never log a token, key, nonce, proof or `server_sig` at any level — `TestLogin_NoSecretsInLogs` runs at debug.

**Atomicity.** `Store.Admit`, `Store.Revoke` and `Store.ExpireSweep` run their callbacks under the store lock and the callbacks must not call back into the Store; `authService.idxMu` nests inside it. Revoke phase 1 (write, then `markRevoked`) silences conns via `AuthState.Revoke` (`wantsFrame`, `Conn.Send`, `SendDroppable` and `SendBlocking` drop all but `error`; frames queued before it, at most the send buffer, may still be written); phase 2 sends the reason and closes on workers. `connDrainTimeout` is derived from the backoff cap plus the refusal flush, so `Stop` outwaits a proof check caught in its backoff; `acceptTCP` counts a conn in `handling` before its `Accepted` hook. Expiry is the same two phases on a one-minute ticker (`expiryLoop`, injected tick and clock), with `token_expired` audited once per token per daemon run.

**Read-only means no side effects.** A read-only attach never bootstraps a tab, never writes `clientSize`, never kicks a pane (nor does its output hold's overflow path in `releaseOutputHold`), never clears `GhostSnap`, never records a CWD. View handlers answer from existing buffers (`not_running`, via the one `paneRunning` predicate, caller holds `PluginMu`), never call `ensurePaneSpawned` and never highlight. A new view handler that can spawn, write or resize needs a read-only branch.

**Identity.** Client ids are bound to their principal (`clientRecord.principal`, `reservation.principal`); a TCP claimant of an id held, or grace-reserved, by another principal is refused with `client id in use`, audited once per (conn, type) per minute like every refusal (`refuseAttach` goes through `ShouldAuditRefusal`). The local socket always wins a client id: a local claimant replaces any record with that id. A RESTART reserve (principal unknown) yields the slot only to the local principal; a TCP claimant of a restart-reserved id is ADMITTED as an ordinary client without the slot (refusing it would strand a remote TUI, which never retries an attach). While such a record is shadowed (`shadowedLocked`), every state frame publishes `reservedMasterMarker` (`reserved-for-local:<id>`, padded past `maxClientIDLen` so it names no client) instead of the id — publishing `""` would make every TUI leave follower mode while the reserve still drops every resize. A TCP attach never clears a restart reserve. A read-only record is never eligible, never takes control, never changes geometry. Each local conn has its own `AuthState` (no shared singleton): the refusal-audit rate state dies with the conn.

**Standard rights.** Raw `instance_args` and `overlay` are refused for every plugin, in all four create shapes (`carriers`); `TestCreatePayloads_EveryFieldAudited` makes a new create field fail until it is classified. The TUI sends toggle NAMES and `kube_context`; `applyNamedSelections` resolves them before any create branch (a refused worktree create still answers `create_pane_resp`). Do not reintroduce client-side folding of toggles into `instance_args`.

**Hardening.** Unix: a failed socket chmod stops the daemon. On Linux `listenUnixPrivate` binds under umask 0077 while holding `syscall.ForkLock` for writing (no child forked in the window inherits 0077; concurrent callers cannot lose the restore); on darwin and other Unix it does not touch the umask (net takes `ForkLock` for reading there, so the write lock would deadlock) and relies on the immediate chmod plus the 0700 `QUIL_HOME`. Windows: `ProtectDir(QUIL_HOME)` runs in `Daemon.Start` before the socket, `tokens.json` or `audit.log` is created (`quild.lock`, `quild.pid`, `quild.log` and `quild.stderr.log` already exist and are covered by propagation), and re-applies a PROTECTED inheritable DACL on every start — on an upgraded install that rewrites every inheriting file and folder of the existing tree to owner + SYSTEM (explicit entries on a file survive). Only `tokens.json` is created WITH the owner-only descriptor (`CreatePrivateFile`, via its temp file); `audit.log` gets `ProtectFile` after the `RotatingWriter` opens it, and its rotated archives rely on the folder's inherited DACL. A socket ACL failure is a warning only while `QUIL_HOME` reads back owner-only (`DirAccessWarning`, which compares SIDs by value and treats a NULL DACL as foreign) and stops the daemon otherwise — which is what a FAT/exFAT `QUIL_HOME` hits. Windows enforces the socket file's own ACL: verified 2026-10-03 on Windows 10 build 19045 by the two-account test in `docs/security.md` (`TestACLTwoAccount`, manual; it never alters an existing directory's ACL) — a second account was refused on the protected socket and accepted on the permissive one.

**Listener.** `[listener] tcp` goes through `debugserver.LoopbackAddr` BEFORE anything binds (each caller passes its own reason text), and `StartTCP` refuses a non-loopback bind again after it. The listener starts only when both `tokens.json` and `audit.log` opened, `audit.log` was restricted to the owner (`protectAuditFile` failing is an open failure), and `ProtectDir(QUIL_HOME)` succeeded (`homeUnprotected`); any failure leaves the unix socket alone. Audit lines about conns that have NOT logged in (`tcp_connect`, `login_failed`, their `tcp_disconnect`) go through `writePreLoginAudit`, capped daemon-wide at `preLoginAuditPerMinute` (120) per fixed minute; the rest are counted into one `audit_suppressed` line (written by the next pre-login line, the expiry tick, or `closeAuth`). Anyone on loopback can fail logins without a token, and uncapped they would rotate the logins and privileged requests out of the log. `login_ok` and everything after it stay uncapped. `closeAuth` stops the expiry loop and waits for it before closing the audit log, so a sweep at shutdown keeps its `token_expired` line. `Stop` waits (bounded) for the conns' disconnect callbacks before closing the audit log they write to.

**Client.** `quil --connect` sets `remoteDest = "tcp:<addr>"` so every `--remote` guard applies (`daemon`, `clients`, `restart`, `status`, `mcp`, `sandbox`); it never calls `gateVersionCheck` (no restart, spawn or install — `gateTCPVersion` only refuses a mismatch) and never applies a staged update at launch (`applyStagedAtLaunch`: the respawn would lose the token). `QUIL_TOKEN` is unset at the top of `main` (a failure is logged by name, never value); the token is never read from argv. A `[[destinations]] dest = "tcp:…"` entry is skipped, with a log line, by both the launch extras and the MCP bridge's hosts — both dial over ssh, and only `--connect` holds a token. The refusals of `restart`, `status` and `mcp` name `--connect` and give no `ssh tcp:…` advice under it. The login hello is `helloPayload` — the same builder `sendHello` uses. `dialTCP` closes the client on every login error, and every dial path (launch, `dialTCPDest`, `redialTCPDest`) logs the full error — the daemon's refusal reason, never the token — to `quil.log`, since `describeConnectError` drops it from the one-line message. A refused or unproven re-login is `ErrLinkPermanent`; connection refused is transient. Every login's `hello_resp` rights ride back with the conn (`tui.LoggedIn`) and are re-applied, so a reconnect picks up the token's current level. The TUI's `Router.Send` drops non-view types for a read-only destination (keyed by the conn actually chosen, sole-conn fallback included); every workspace change aimed at one is refused locally with `readOnlyFlash`, before any local side effect; the palette and context menus grey create/close/rename; a viewer follows the project of the daemon's ACTIVE TAB (`followedProject`), not the daemon's active project. A read-only destination is ALWAYS a follower (`isFollower`), master or not: a lone viewer leaves `size_master` empty, and without that it would size VTs to its own boxes with no PTY resize to pair. A standard (or read-only) destination cannot start an overlay or a plugin instance (`destCanRawArgs`): the key, the instance step and the submit refuse with `noRawArgsFlash` (the dialog closes so the flash shows), and the lazygit/hunk palette and pane-menu rows are greyed unless the tab already runs that overlay, which standard may still show or hide. Admin-class actions (stop daemon, plugin reload, kill process) are refused locally with a flash for read-only AND standard via `destCanAdmin`, and `overlayPolicyCmd` skips such a destination silently (it is pushed on every attach and Settings commit, and each refusal would be audited); rights checks with no pane of their own use `rightsDest`, which falls back to `homeDest` before the first broadcast.
