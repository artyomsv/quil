## Resolved (fixed in code; do not re-raise)
- [code-quality/I-1] `renderStyledSegments` summed independently measured segment widths, which understates a row when a segment starts mid grapheme cluster (U+FE0F measures 0 alone and makes the pair before it 2). The reviewer's proposed fix — measuring an accumulated plain prefix — was MEASURED and rejected: whether the runes rejoin depends on the styles, not the text (an SGR emitted between them separates them), so at w=3 over `{"⚠", "️"}` the row is 3 cells coloured and 4 plain and no single measurement is right for both. Resolved as an explicit caller PRECONDITION on the doc comment plus `TestRenderStyledSegments_SegmentsMustStartOnAClusterBoundary`, which pins the divergence so a later "correction" finds the reason — round 1
- [code-quality/I-2] Per-frame allocation: `lipgloss.Style` is 648 bytes (measured), so `styledSegment` is 664. `projectRow` grew a nil slice through four appends then copied it into a fifth to prepend the head — ~8 KB churn per project per frame on a strip repainted every spinner tick. Now one `make([]styledSegment, 1, 5)` with slot 0 reserved for the head; `renderStyledSegments` ranges by index instead of copying a 664-byte value per iteration — round 1
- [code-quality/I-3] `t == "" → continue` conflated "empty segment" with "did not fit", so a segment whose first cluster exceeded the budget was DROPPED and the next rendered in its place — one state's glyph in another state's position. Split into `s.text == "" → continue` (not a budget event) and `t == "" → break` (row ends). Pinned by `TestRenderStyledSegments/a_segment_that_cannot_start_ends_the_row`, verified to fail under the old `continue` — round 1
- [code-quality/S-4] `projectRow`'s trailing-pad comment claimed the pad fires "when the badge was cut away entirely", which is impossible (the head then consumes the whole budget). Corrected to the real case — the last segment giving up a cell it could not use — with the concrete repro `projectRow("a", 0, 0, 0, "⚡", false, 5)` — round 1
- [code-quality/S-5 + qa] `linkGlyphStyle`'s `default` returned the idle colour with nothing pinning it, so a third link state added to `linkGlyph` would silently render as healthy. Hoisted to `linkGlyphStyles`, a map both the function and `TestLinkGlyph_EveryStateHasItsOwnColour` read; the test drives `linkGlyph` over every `reconnectState` combination and asserts each glyph it can produce is paired, distinct, and not the fallback colour — round 1

Added a 10-case table covering `w <= 0`, negative w, nil/empty segments, an empty-text segment, mid-text truncation, an earlier segment not sacrificed for a later one, a wide glyph straddling the boundary, and a segment that cannot start — round 1
